# Алгоритм шифрования на основе факториальной системы счисления (ФСС)

Учебно-исследовательский прототип симметричного шифрующего ядра, в котором
факториальная система счисления (ФСС) используется не как самостоятельный шифр,
а как **внутреннее состояние** ключезависимого преобразования. Ядро встроено в
законченную гибридную криптосистему и сравнивается с **AES-GCM-256** и
**Кузнечик-CTR** в едином интерфейсе.

> ⚠️ Проект носит исследовательский характер и **не является промышленным
> средством защиты данных**. Сама по себе ФСС секретности не даёт — это
> обратимое представление числа. Криптографические свойства обеспечивают
> добавленные элементы: перемешанный по ключу алфавит, nonce и раундовый слой.
> Стойкость ядра оценивается экспериментально (лавинный эффект, чувствительность
> к ключу) и не подкреплена независимым криптоанализом.

Работа выполнена как выпускная квалификационная работа (ВКР) на кафедре ВММБ ПНИПУ.

## Что внутри

- **ФСС-ядро** — текст → длинное число (алфавит мощности 256) → коэффициенты ФСС
  (последовательные деления) → сериализация → 8 обратимых ключезависимых раундов
  (ключевой поток по модулю 256, S-box, перестановки, диффузия). Блочная
  обработка, рабочая длина блока — 1096 символов.
- **Гибридная схема** — согласование общего секрета через **ECDH (NIST P-256)** и
  вывод ключевого материала через **HKDF-SHA256**. Симметричный ключ по каналу не
  передаётся.
- **Цифровая подпись** — **ECDSA** по каноническому представлению пакета.
- **Доверенные связи ключей** — ручная модель доверия (без сертификатной
  инфраструктуры).
- **Формат передачи** — JSON-пакет; опционально внешняя обёртка **Reed-Solomon +
  CRC32** для обнаружения и восстановления повреждений.
- **Три ядра в одном интерфейсе** — ФСС, AES-GCM-256, Кузнечик-CTR — для сравнения
  по размеру результата, скорости, лавинному эффекту и чувствительности к ключу.

## Технологии

| Компонент | Назначение |
|-----------|------------|
| .NET 8, WPF | Среда выполнения и графический интерфейс (десктоп, Windows) |
| System.Security.Cryptography | ECDH, ECDSA, AES-GCM, SHA-256, HMAC-SHA256, генерация случайных байтов |
| OpenGost.Security.Cryptography | Блочный шифр Кузнечик (ГОСТ Р 34.12–2015) |
| ReedSolomon | Внешняя помехоустойчивая обёртка |
| System.IO.Hashing | Вычисление CRC32 |
| System.Text.Json | JSON-пакеты передачи и файлы настроек |

## Сборка и запуск

Требования: **Windows**, **.NET 8 SDK**.

```bash
git clone https://github.com/Kettle1703/FNS_graphics.git
cd FNS_graphics
dotnet build FNS_graphics.sln -c Release
dotnet run --project FNS_graphics
```

Либо открыть `FNS_graphics.sln` в Visual Studio 2022 и запустить (F5).

## Как пользоваться (кратко)

1. В окне настройки связей создать связь с получателем и внести его публичные
   ключи (ECDH и подписи), сверив их по доверенному каналу.
2. В окне режимов выбрать ядро шифрования и параметры пакета (создание JSON,
   Reed-Solomon, цифровая подпись).
3. В главном окне ввести текст и нажать «Шифровать» — получить JSON-пакет.
4. Для приёма выбрать JSON-файл: приложение проверит подпись, при необходимости
   восстановит пакет через Reed-Solomon и выполнит дешифрование.

## Ограничения

- Исследовательский прототип, а не промышленное средство защиты.
- ФСС-ядро заметно медленнее AES-GCM-256 и Кузнечик-CTR из-за длинной арифметики.
- Закрытые ключи хранятся в файлах — для реального применения нужно защищённое
  хранилище ОС или менеджер секретов.
- Ручная модель доверия — пользователь сам проверяет подлинность публичных ключей.
- Независимый криптоанализ не проводился; стойкость оценена только эмпирически.
